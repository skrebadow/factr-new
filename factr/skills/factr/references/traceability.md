# Traceability reports and revision impact

## Set the report population

Choose the source clauses and output units for the requested report. A "See tab X" cell identifies a reference to inspect; use available tab content for the allocation and identify an unavailable target as an unresolved portion.

In source-detail cells, use the relevant clause or excerpt instead of a test summary.

## Describe allocation relationships

When useful, describe a source/output link as direct, aggregated from several clauses, decomposed from broader scope with a derivation, or refinement-derived where extra specificity rests on another source.

These precision labels classify relationships, not the whole assertion's support, evaluation or acceptance. An output can have a direct configurability link and refinement-derived actor/range details; retain the basis for each part.

Review source-to-output matched portions and output-to-source bases. Use gap fields for the source behavior omitted by a grouped output and for output details without a source allocation.

## Distinguish the reported coverage layers

Use separate columns or sections for source allocation, test challenge coverage, automation readiness and actual result applicability when those layers are in scope.

For counts or proportions, identify the population and counting rule. Requirements with any link, fully addressed clauses and tested conditions are different denominators.

## Trace revision dependencies

For an impact view, identify each result's consumed input units and revisions, including shared context, evidence and intermediate derivations that a requirement link may omit.

Show paths from a changed basis through allocations or assertions, procedures, bindings and shared conclusions as applicable. Identify the particular detail needing reassessment at each dependent unit.

Assess the dependency group in a cycle without endless traversal. Missing or stale edges leave the group's impact/reuse assessment incomplete; an omitted edge is not an independence result.

Keep per-unit provenance in mixed-revision bundles. If a consumer requires one snapshot, partition or regenerate for that contract instead of relabeling old content. A digest or summary cannot replace unavailable consumed content.
