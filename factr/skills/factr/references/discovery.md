# Targeted discovery for procedures and bindings

## Select the inspection target

Locate the contract, code, configuration, fixture, access description or record nearest the missing procedure detail. Expand inspection when that source leaves a material question unresolved.

Useful targets include submission operations and input shapes, same-resource outcome reads, correlation keys, observation windows and existing machine bindings.

A technology name does not identify a usable operation. Inspect its parameters, result interpretation and target applicability before replacing an open procedure step.

## Apply the finding to the affected detail

Record which procedure detail a finding resolves and the source/target revision. A schema identifying retention's field and range can refine the data while leaving the wrapper, submission route and access unresolved.

Prefer logical resource identifiers over transient instance values when they improve reuse. Record credential references or configuration locations rather than secret values.

## Bound runtime discovery

Contract or fixture inspection is different from submitting data, restarting a process or changing state. For an authorized runtime probe, specify the target, actions, run count, observations and necessary reset or cleanup.
